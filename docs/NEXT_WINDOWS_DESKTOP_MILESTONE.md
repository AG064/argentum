# NEXT02: governed Windows desktop workflow

Inactive until the owner forwards this instruction. This document does not
authorize implementation, live requests, application access or a new allowance.

Start from the delivered NEXT01 identity and its actual acceptance record.
Preserve original stores, checkouts, indexes, releases and browser evidence.
Do not reopen completed comparison or browser tasks. Confirm which desktop
applications and bounded work the owner places in scope before acting.

Implement one complete non-browser Windows workflow through normal Argentum
tools. Reuse native policy, opaque owner authority, lifecycle, jobs, cancellation,
accounting and result infrastructure. Keep adapters optional, inert at startup
and disabled until exact owner review. Do not add generic model shell execution
or an unrestricted input-injection endpoint.

Use maintained Windows UI Automation semantic observation and supported control
patterns first. Bind each action to the observed HWND, process/start identity,
desktop/session, element runtime identity and observation generation. Recheck
focus, visibility, enabled state, geometry and target identity immediately before
effects. A stale window, replaced element, focus loss or owner intervention must
stop or require fresh observation, not retarget coordinates automatically.

Keep screenshot bytes inside explicit application/desktop disclosure scope and
the supported model image-input path. Screenshots can contain secrets; there is
no universal redaction guarantee. Never inspect secure desktop, inject passwords,
bypass elevation/integrity boundaries, copy another application's sessions or
operate unrelated personal applications. Narrow OS input is an explicit fallback
with separately reviewed action types, not general authority.

Offline controls must exercise actual UI Automation against an owned synthetic
native application, including multiple windows/processes, stale identities,
DPI/multi-monitor coordinates where available, focus changes, unexpected dialogs,
denied applications, cancellation, no late effects and owned teardown. Do not
infer physical multi-monitor or elevated-app coverage from headless mocks.

Freeze a useful unseen non-browser task, public requirements and independent
acceptance before its final live attempt. Argentum must observe, act, verify the
actual resulting artifact/application state and report uncertain effects through
its own tools. Do not substitute an outside operator for missing actions or
claim success from a screenshot alone. Preserve failures and distinguish source,
semantic result, visual evidence, approvals and supervisor assistance.

Use only the existing approved model/account. A separately confirmed finite
request, foreground-time and external-action allowance is required; closed
allowances do not reset. No purchases, provider switch, broad permissions,
credential export, signing, release, default-branch merge or publication without
new explicit authorization.

Deliver a reviewed implementation, separately identified optimized executable,
exact commands, the supported authority/access boundary, actual end-to-end
evidence, preservation, consumption and remaining gaps. Native application
control is a separate acceptance gate from browser development and does not by
itself establish general Codex replacement readiness.
