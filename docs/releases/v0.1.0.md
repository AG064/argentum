## 2.What's Being Done

### 2.1 Router Agent — Production Integration

The Router Agent (`src/agents/router/`) routes messages to different agent sessions based on sender ID, chat ID, keyword, or chat type. It was designed but never connected to the main agent loop.

**Goal:** Wire it into `src/index.ts` so Argentum can serve multiple users with isolated workspaces from a single instance.

Tasks:

- [ ] Create `config/router.yaml` with default routing rules
- [ ] Integrate RouterAgent dispatch into the main Agent's `handleMessage()` flow
- [ ] Add workspace-per-user isolation in the session layer
- [ ] Test with 2+ Telegram users routed to different agent sessions
- [ ] Document multi-user setup in docs/

### 2.2 Knowledge Graph — Unified Architecture

Three separate graph implementations exist:

- `src/core/knowledge-graph.ts` — bitemporal versioning (entities + relations with valid_time/transaction_time)
- `src/memory/graph.ts` — OMEGA Memory integration (typed-edge memory linking)
- `src/features/knowledge-graph/index.ts` — feature module (import/export, BFS pathfinding)

**Goal:** Determine which is the canonical graph and which are specialized backends. Design a unified Graph API that all three can implement.

Tasks:

- [ ] Audit what each graph is actually used for in production code paths
- [ ] Define a common `GraphBackend` interface
- [ ] Keep bitemporal graph as the primary audit/provenance layer
- [ ] Merge OMEGA-style memory linking into the feature module or core
- [ ] Remove duplication (likely the simple `graph.ts` is absorbed)
- [ ] Update docs/FEATURES.md graph entry
