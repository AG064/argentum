# Argentum 0.1.0 draft

Status: engineering draft, not a published release

Argentum 0.1.0 starts the native Rust product line. It is a CLI-first agent
harness with a Slint desktop client that uses the same command host in process.
The desktop app does not add a subprocess or JSON serialization cost to normal
interaction. JSONL protocol version 1 remains available for automation and
external clients.

## Draft product contract

The 0.1.0 draft is built around four boundaries:

1. One typed command and event contract for the CLI and desktop client.
2. A workspace security boundary that the model and UI cannot bypass.
3. Durable workspace, session identity, and ordered conversation history before
   search or change review is added.
4. A native design system driven by Argentum's approved A/G identity, graphite
   and silver structure, and red reserved for execution and attention.

## Included foundation

- Native Rust workspace and Slint interface with no WebView or JavaScript
  runtime.
- In-process `CommandHost` client plus bounded persistent JSONL server.
- Streaming OpenAI-compatible provider path, with LM Studio as the default
  local configuration.
- Typed read and write tool requests through the command boundary and a bounded
  model-driven tool loop for OpenAI-compatible providers.
- Workspace-bounded file access and explicit approval before writes.
- Honest command failure outcomes for CLI and JSONL callers.
- SQLite event and layout storage.
- Durable workspace-scoped sessions with CLI listing and selection.
- Durable project and session-scoped conversation messages, restored after
  restart and supplied as ordered multi-turn model context.
- A persisted, bounded session goal contract with objective, lifecycle,
  token/tool/time budgets, iteration metadata, next action, verification count,
  and pause, resume, replace, or clear controls through the shared host.
- One active run per session, duplicate submission and approval latches, and
  cancellation cleanup.
- Bounded non-billable provider connectivity probing.
- Workspace-scoped provider profiles with durable selection, safe endpoint
  validation, CLI management, native settings editing, and selected-provider
  task routing.
- Provider-scoped model catalogs and durable model selection through the CLI,
  JSONL protocol, and native settings surface. Model selection does not change
  the selected provider profile.
- Separate bounded reasoning and answer streams, including fragmented tagged
  reasoning fallback, explicit provider reasoning fields, and persistent
  collapsed reasoning disclosure.
- Exact provider-reported input, output, total, cached, and reasoning token
  accounting. Known context limits are shown exactly and unknown limits remain
  labeled unknown.
- Exact-profile in-memory credential routing for OpenAI, MiniMax, and DeepSeek.
  Secrets are not copied into profiles, events, protocol JSON, logs, or SQLite.
- Workspace-scoped secure credential commands that read secrets from standard
  input and persist them through the operating-system keyring.
- A bounded Rust harness registry with stable capability and surface IDs,
  dependency validation, named presentation profiles, and factual unavailable
  reasons.
- Additive protocol-v1 commands plus CLI and native Settings controls for
  profile selection and explicit Activity or Changes visibility. Presentation
  state never grants runtime authority.
- Compatibility loading for the saved v0.0.9 workspace and its configured
  MiniMax credential, without changing the legacy secrets file.
- Desktop event-lag recovery, ordered transcript restoration, follow-tail
  behavior, Enter to submit, Shift+Enter for a new line, and duplicate-action
  protection.
- Session-scoped run errors and active-run snapshots, so lag recovery and
  background runs cannot overwrite the visible session state.
- Native Windows build and clean-staging launch validation scripts.
- Argentum 0.1.0 visual contract and canonical brand asset pipeline.

The current implementation and validation evidence determine whether each item
is release-ready. This document does not turn an unfinished path into a feature.

## Functionality being migrated from 0.0.9

The first migration slices are deliberately narrow:

- durable workspace and session identity;
- session index publication through the shared command host;
- durable ordered conversation messages and multi-turn context;
- a bounded session goal contract with explicit lifecycle controls, without
  automatic continuation or model-authored completion claims;
- model-provider connectivity probing without a billable model request;
- durable nonsecret provider profiles and explicit selection through the shared
  command host;
- provider-scoped model discovery and selection through the same command host;
- separated model reasoning and exact reported context usage;
- canonical Argentum app identity across the native interface and Windows
  executable;
- provider and permission state presented with factual copy;
- existing approval and workspace isolation behavior retained in the new host.
- configured MiniMax probe and streaming verification through the same command
  host used by desktop.

See [the migration matrix](../V0_0_9_MIGRATION.md) for the complete boundary.

## Not yet part of the 0.1.0 draft claim

- recovery of an in-progress run after process restart;
- real changed-file accounting, unified diffs, accept or restore actions, and
  verification runners;
- native credential entry and automatic migration from the legacy secrets file;
- GGUF filesystem discovery and managed local model lifecycle;
- OpenClaw import, updater application, or full localization;
- MCP, third-party skill installation, browser control, computer control, or
  scheduled-task UI;
- Telegram, Discord, Slack, WhatsApp, standalone dashboard, or multi-agent
  dispatch;
- active Android, macOS, or Linux release artifacts.
- user-installed external modules or dynamic in-process plugin loading.

## Publication gates

Before 0.1.0 can be called a release candidate, all of the following must be
true:

- `cargo fmt --check` passes.
- `cargo check --workspace --locked` passes.
- `cargo test --workspace --locked` passes.
- `cargo clippy --workspace --all-targets --locked -- -D warnings` passes.
- CLI version, status, session state, failure, and JSONL protocol smokes pass.
- The isolated configured MiniMax smoke passes without printing or persisting
  the credential and restores its original provider selection.
- The packaged Windows executable launches from a clean staging directory.
- The Windows executable and UI use the canonical Argentum identity asset.
- Native visual checks cover desktop, compact desktop, tablet, and phone-sized
  layouts in empty, running, approval, error, and reduced-motion states.
- The root license file and Cargo package license metadata agree. They do not
  currently agree, so redistribution claims remain blocked until the owner
  selects the intended license expression.

## Draft versioning

Workspace packages use version `0.1.0`. Protocol version 1 is independent from
the package version. Additive event variants must remain backward compatible;
breaking request or response changes require a protocol-version decision.
